# AI Rule Mapping

Read the requested rule and inspect the project's actual instruction/checking surfaces. Determine whether it is a project convention, task-local constraint, deterministic quality check or a requirement for host enforcement. Keep its scope and exceptions explicit.

For a convention, propose concise AGENTS.md wording in the smallest appropriate scope. For a deterministic rule, use an existing linter/test/build mechanism when it is already available and the user requests implementation. For a task-local constraint, state and apply it in the current chat. Behavioral instructions do not enforce an OS/network boundary.

Do not install lifecycle hooks, hook engines or observers, and do not invent an equivalent host event API. If mandatory host interception is essential but unavailable, identify that limitation. Apply only requested persistent changes, preserve existing rules and verify the actual check or resulting guidance. CLAUDE.md remains an import-only compatibility shim if present.
