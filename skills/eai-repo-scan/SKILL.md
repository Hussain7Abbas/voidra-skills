# AI Repository Inventory

Inspect the selected root and repository instructions. Use available file listing/search and manifests to map languages, modules, build/test entry points, generated/vendor areas and external dependencies. Bound large scans and report sampled or excluded areas. Read symlinks carefully; do not leave the authorized root or inspect secret contents just to count files.

Separate first-party source, checked-in third-party/generated code and dependency declarations using actual evidence. Detect potential duplication, oversized responsibilities, unused-looking areas and missing ownership/tests as review candidates, not automatic deletion targets. File size or absence of a text reference does not prove code is dead.

Return a navigable structural overview with representative paths, measured counts/units, dependency/ownership boundaries and prioritized investigation steps. Label uncertain inferences and unavailable language-specific analysis. No upstream repo-scan package, installer or root script is required; use existing project tools when they add useful evidence. Implementation, deletion and dependency changes require the user's requested scope.
