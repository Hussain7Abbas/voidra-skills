# Lessons that improve the working environment

Use actual authorized task evidence. Explain the mechanism and a recognizable signal,
then classify the proposed improvement: navigation pointer, existing deterministic check,
judgment guidance, missing information access, or no durable change. Inspect the project's
existing checks before adding another mechanism.

A mechanical pattern usually belongs in the existing linter/test/build lane; a judgment
call needs scoped guidance and a counterexample. Compare with existing lessons and merge
equivalent causes rather than accumulating rules. Distinguish incident prevention from
polish. Record expected benefit, applicable scope, owner and observable verification for
substantive follow-up work. Do not claim success merely because a lesson was written.

Respect current authorization: proposals do not register hooks, read unrelated sessions,
modify global instructions or automatically start another skill. Retain the project's
existing historical/lesson owner; do not add a diary for every change.

Reference: [postmortem follow-through](https://sre.google/workbook/postmortem-culture/).
