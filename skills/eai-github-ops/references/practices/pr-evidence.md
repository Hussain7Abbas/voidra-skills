# Pull-request evidence

Lead with the problem and resulting behavior. Reuse the repository template. Include the
smallest concrete before/after evidence that demonstrates the change; visual evidence is
useful for a visual change, a diagram only when it clarifies structure. Scale the body to
the change rather than forcing fixed headings on a small fix.

Reuse actual test/verification output and risk analysis already produced. For material
risk, name affected consumers/data, rollback steps and any irreversible consequence;
one-word blast-radius labels cannot replace that explanation. Distinguish integration
into develop from an authorized production promotion to main. Report unverified paths.
Writing a PR description grants no authority to publish, merge, release or notify people.
