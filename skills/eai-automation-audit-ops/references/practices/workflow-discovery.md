# Workflow discovery and checkpoints

Identify the recurring activity, actual trigger, input, useful output, exceptions and
cost of failure. Monthly, event-driven and human-reviewed work can be legitimate; frequency
alone is not a veto. Start from a real example before designing infrastructure or AI use.

Define what can be checked mechanically and what needs human judgment. Prepare maximal
reversible work before asking for a decision, but place approval before the risky action
it governs. A checkpoint presents a short decision brief, the reviewable artifact, evidence,
uncertainty and the consequence of approval. Neither elapsed time nor a default is consent.

Specify stop conditions, bounded retries, duplicate-run protection and recovery for the
actual workflow. Run a small authorized case before expanding. Discovery is a design;
it does not create a timer, connect a service or execute ADL. The ADL reference remains the
language authority; an audit consumes existing workflow facts rather than inventing scope.
